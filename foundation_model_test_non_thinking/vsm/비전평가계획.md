# 비전 평가 상세 계획 (Image-to-Text)

> 두 원안 합본:
> - **Plan #1 — VLMEvalKit/EvalScope 기반 평가 프레임워크** (구현 코드 80% 완성)
> - **Plan #2 — 한국어 금융권 특화 평가 체계** (3개 업무 카테고리, 벤치별 native 축)
>
> 본 문서는 6개 소형 멀티모달 모델 대상 image-to-text 평가의 **단일 합본 실행 계획**이다.

---

## 1. 개요

### 1.1 목적

사내 도입 검토 대상 한국어 Vision-Language 모델 6종의 image-to-text 품질을 객관·재현 가능하게 측정한다. 다음 의사결정을 지원한다.

- 업무 투입 가능 모델 식별 (Go/No-Go가 아닌 **용도별 추천**)
- 모델 버전 간 회귀(regression) 조기 감지 베이스라인 확보
- Qwen3.5 ↔ Qwen3.6 세대 / Dense ↔ MoE 아키텍처 / 27B ↔ 35B 사이즈 효과 분리

### 1.2 적용 범위

- **포함**: image-to-text (OCR · 문서 이해 · 표/차트 · 실세계 장면 텍스트 · 서술형 VQA)
- **제외**: 영상 이해, 이미지 생성, 음성, 임베딩

### 1.3 평가 원칙 (Plan #2 유지)

- **재현 가능성**: 공개 벤치마크 동일 조건 재측정 가능
- **업무 정합성**: 금융권 실무 이미지(문서·표·차트·영수증) 우선
- **자동화**: 정기 회귀 감지 자동 실행 가능
- **다축 평가**: 단일 점수 아닌 카테고리별 서브스코어 병행

### 1.4 핵심 결정 사항

1. **VLMEvalKit (EvalScope) 사용** — Qwen 공식 published 점수와 직접 비교 가능
2. **한국어 우선** — 영어 벤치마크는 보조 cross-check만
3. **축 합산 금지** — 문서 OCR·구조 이해 / 실세계 장면 텍스트 / 자유 서술형을 벤치별 native 단위로 병렬 보고
4. **6모델 균등 적용** — Plan #1의 단일 모델 프레임워크를 6개로 확장
5. **GPUStack OpenAI-compat API + CustomAPIModel** 연결 방식 그대로 채택

## 3. 평가 체계

### 3.1 3개 업무 카테고리 + 독립 발행 축

| 카테고리 | 발행 방식 | 사내 업무 매핑 |
|---|---|---|
| **문서 OCR·구조 이해** | 벤치별 accuracy와 분자/분모 | 약관·계약서·재무제표·표·차트 처리 |
| **실세계 장면 텍스트** | 벤치별 native metric | 모바일 업로드 사진(영수증·명함·고지서·간판) |
| **자유 서술형 종합 역량** | KOFFVQA 0–10 rubric, 인간 검증 전 PROVISIONAL | 대화형 응답, 회귀 스크리닝 |

카테고리와 벤치 사이 평균·가중 합산은 하지 않는다. 서로 다른 데이터셋의 난이도와
판정 척도가 같지 않으므로 단일 종합 점수는 비교 가능한 양이 아니다.

### 3.2 2 트랙 구조

- **트랙 A — 공개 벤치마크** (VLMEvalKit, 자동 채점)
- **트랙 B — 커스텀 테스트** (자체 구현, 트랙 A에서 누락된 실무 평가)

## 4. 트랙 A: 공개 벤치마크 (VLMEvalKit)

### 4.1 메인 — 한국어 6종 (Plan #2)

| 벤치마크 | 카테고리 | 측정 내용 | 메트릭 | 샘플 수 |
|---|---|---|---|---|
| **K-DTCBench** | 문서 OCR | 컴퓨터 생성 + 수기 문서·표·차트 (유형별 80문항) | Accuracy | 240 |
| **KO-VLM-Benchmark** | 문서 OCR | KO-VQA(문서 이해) + KO-VDC(시각화 도식) + KO-OCRAG(복잡 문서 OCR) | Accuracy / ANLS | ~1,500 |
| **KRETA** | 문서 OCR | 15영역 × 26 이미지 유형 텍스트 리치 VQA | Accuracy | ~2,000 |
| **MTVQA(KR)** | 실세계 장면 | ByteDance 9개 언어 중 한국어 서브셋 (간판·영수증·안내판) | Accuracy | ~1,000 |
| **K-MMBench (선별)** | 실세계 장면 | 표·차트·영수증·표지판 카테고리만 선별 (신원 추론·감정 분석 제외) | Accuracy | ~800 |
| **KOFFVQA** | 자유 서술형 | 275문항 객관 Rubric 채점 (GPT 심판 편향 완화), 10개 VLM 역량 축 | Rubric Score | 275 |

소계: 약 **5,800 샘플 / 모델**

### 4.2 보조 — 영어 cross-check 2종

> Plan #2가 한국어 우선이라고 명시했으므로 **참고 지표로만 사용**한다. Qwen 공식 점수와 직접 대조해서 환경 세팅이 깨지지 않았는지 검증하는 용도다.

| 벤치마크 | 용도 | 샘플 수 |
|---|---|---|
| **POPE** | 환각 측정 cross-validation (트랙 B-1 보강) | ~9,000 (서브샘플 1,000으로 축약 가능) |
| **OCRBench** | 영문 OCR 베이스라인 (Qwen published 점수 비교) | 1,000 |

### 4.3 벤치별 발행 규칙

```
K-DTCBench / K-MMBench / MTVQA(KR) / KRETA = correct_measured / attempted
KOFFVQA judge = 0–10 정수 rubric의 평균 — PROVISIONAL
B-3 = JSON parse / schema / value 축을 각각 표시
B-4 = condition별 TTFT / total / tokens-per-sec percentile을 각각 표시
```

오류가 하나라도 있으면 strict와 conditional 수치를 모두 숨긴다. 서로 다른 벤치나 축을
평균·가중 합산하지 않으며 상세 게이트는 `MULTIMODAL_PUBLISH_CONTRACT.md`를 따른다.

## 5. 트랙 B: 커스텀 테스트

> Plan #1의 4개 모듈 그대로 채택. 트랙 A에서 측정 어려운 실무 항목 보강.

### B-1. 환각률 (사내 이미지)

- **트랙 A의 POPE는 자동 OK** → 여기는 사내 이미지 50~100건 수동 샘플링
- 이미지에 없는 객체/텍스트 질의 → 거짓말하는지 측정
- 메트릭: Accuracy / F1 / **Yes-bias율** (yes 편향)

### B-2. 한국어 VL 자체 골든셋

- 한국어 간판/문서/UI 스크린샷 OCR — 50건
- 한국어 이미지 설명 생성 — 50건
- 한국어 문서 이미지 QA — 50건
- 이미지 소스: AI Hub 한국어 OCR 데이터셋 + 사내 익명화 샘플
- 평가: **LLM-as-Judge (GPT-4o) + 사람 평가 병행**, 이견 케이스만 사람 확정
- 메트릭: CER / WER / 자연스러움 1~5점 / 정답률

### B-3. 포맷 준수 (Structured Output)

- 표 이미지 → JSON 변환 — 30건
- 영수증/인보이스 → 구조화 추출 — 30건
- 차트 → 데이터 포인트 추출 — 20건
- 메트릭: **`json.loads` 파싱 성공률** + 필드 정확도 + 스키마 일치율

### B-4. 지연시간 프로파일링

- 4 조건: 텍스트-only / 256px 저해상도 / 1024px+ 고해상도 / 다중 이미지(2~4장)
- 조건당 50회 반복
- 메트릭: **TTFT** / 총 응답시간 / tokens/sec / **P50·P95·P99**

소계: 약 **600 샘플 / 모델** (latency 200회 포함)

## 6. Gemma 4 visual token budget 추가 트랙

> Gemma 4 두 모델만의 고유 변수. Qwen 모델에는 해당 없음.

- Gemma 4는 이미지당 **70 / 140 / 280 / 560 / 1120 토큰** 중 선택
- **Gemma-4-31B-it / Gemma-4-26B-A4B 한정**: 트랙 A 6개 한국어 벤치마크를 budget **70 / 280 / 1120 3지점**에서 재실행
- 산출: **벤치별 파레토 프론트** (x축 이미지당 토큰 비용, y축 해당 벤치 native metric). 벤치 사이 종합 점수는 만들지 않는다.
- 결과 활용: "Qwen이 Gemma의 어느 budget 지점과 등가인지" 결정 + 운영 시 budget 권장값 도출

## 9. 실행 순서 / 일정

### 9.1 사전 검증 (블로커 조기 식별)

### 9.2 본 실행 순서

```

   2-1. KOFFVQA (275)        ← 가장 빠른 검증

Phase 3: 트랙 B 커스텀 — 빠른 것부터
   3-1. B-4 latency (가장 빠름)

   3-3. B-2 한국어 VL (150)

```

### 9.3 비용 / 시간 추정

- **트랙 A**: 5,800 샘플 / 모델 × 6모델 = **34,800 호출**
- **트랙 A 보조**: POPE 1,000 + OCRBench 1,000 = 2,000 / 모델 × 6 = **12,000 호출**
- **트랙 B**: ~600 / 모델 × 6 = **3,600 호출**
- **Gemma budget sweep**: 5,800 × 3 budget × 2모델 = **34,800 호출**
- **합계**: 약 **85,200 호출**
- 샘플당 2~3초, nproc=4 → 모델당 약 6~8시간, 6모델 순차 시 **48~60시간**

### 10.1 모델별 카드 (6장)
