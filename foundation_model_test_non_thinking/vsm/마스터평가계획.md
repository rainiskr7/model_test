# 소형 멀티모달 모델 6종 평가 계획

> 원안(사내 235B 대체 검증)을 기반으로, **소형 모델 6종 자체 비교 + image-to-text 메인 트랙**으로 재구성한 최종 계획.

---

## 1. 평가 목표

- **핫한 소형 멀티모달 모델 6종의 상대 성능 비교**
- 메인 능력: **image-to-text** (OCR · 표/차트 이해 · 문서 이해)
- 보조 능력: 한국어 LLM 능력 (QA · 요약 · 코드 · 에이전트)
- 산출물: 글로벌 랭킹 + 카테고리 히트맵 + **용도별 추천 매트릭스**
- **Go/No-Go 통과 게이트가 아니라 추천 의사결정**이 목적 (외부 베이스라인 비교 아님)

> **원안과 차이**: 원안은 "235B 대체 검증 + Qwen3.5 122B 도입"이었으나 → 235B / 122B는 비교 대상에서 제외. 6개 모델 자체 비교로 변경.

## 4. 1단계: 인프라 적합성

> **원안 유지** (로딩시간/OOM/timeout/5xx 항목은 원안에서 이미 제외 표시).

### 측정 항목

- 단일 GPU 적재 가능 여부 + 피크/안정 VRAM
- **prefill / decode tokens/sec 분리 측정** (MoE는 decode 빠름 — 분리 안 하면 평균에 묻힘)
- 동시성 1 / 4 / 8 / 16 / 32
- P50 / P95 / **P99** 지연시간
- 8K / 32K / 128K / 200K 긴 컨텍스트 안정성 (RULER 등 진단셋)
- MoE 라우팅 안정성 (요청 패턴 변화 시 throughput 흔들림)
- 비전 입력 시 추가 VRAM / 지연 (이미지당 토큰 비용)

### 산출물

- 6개 모델 × 동시성 5단계 = 30셀 비교표
- 동시성 곡선 그래프 (tok/s, P95)
- VRAM 헤드룸 표

## 5. 2단계: 텍스트 품질

> **원안 골든셋 300~1000개 균등 분배 → 사내 트래픽 분포 기반 비대칭 배분으로 변경**.

### 골든셋 설계 (총 830개)

| 카테고리 | 크기 | 채점 방식 |
|---|---|---|
| 한국어 일반 QA | 200 | 사람 A/B + LLM judge |
| 한국어 요약 (장문) | 200 | 사람 A/B + LLM judge |
| 코드 / SQL | 150 | 자동 채점 (실행 결과/단위 테스트) |
| 긴 문맥 요약 (16K+) | 100 | 사람 A/B |
| 사내 도메인 QA (익명화) | 100 | 사람 A/B |
| 지시 준수 / 포맷 (JSON 등) | 80 | 자동 (스키마 검증) |
| **합계** | **830** | |

> **원안에서 제외 표시된 항목 그대로 반영**: 표/JSON 출력은 "지시 준수/포맷"으로 자동 채점만, 민감정보/보안 가드레일 응답은 평가 카테고리에서 제외.

### 평가 프로토콜

- **6모델 페어와이즈는 15페어 → Bradley-Terry 부분 페어링** 또는 **앵커 모델 1개 vs 5개** 방식으로 비용 절감
- **LLM-as-a-judge 1차 풀평가 → 사람 평가는 의견 갈리는 샘플만**
- 사람 평가자 **3명 이상**, 캘리브레이션 라운드 후 **Cohen's kappa ≥ 0.6** 확인
- 동률(tie) 명시적 옵션 + 이유 코멘트 필수
- 평가 항목별 **별도 보고** (평균으로 뭉개지 말 것):
  - 정답성
  - 환각 여부
  - 지시 준수
  - 출력 포맷 일관성
  - 한국어 자연스러움
  - 재시도 필요 여부

## 6. 3단계: 비전 (image-to-text) — **메인 트랙**

> **원안에는 별도 단계 없음 → 메인 트랙으로 신설**. 평가 목적이 image-to-text라 가장 무거운 단계.

### 평가 카테고리 9개

| 카테고리 | 측정 |
|---|---|
| OCR — 한국어 인쇄체 (깨끗한 문서) | CER (Character Error Rate) |
| OCR — 한국어 손글씨 | CER |
| OCR — 저해상도 / 회전 / 촬영 노이즈 | CER |
| 표 이해 (수치 추출) | 정답 매칭 정확도 |
| 차트 이해 (막대/선/파이 수치 질의) | 정확도 |
| 문서 레이아웃 (다단/각주/머리말) | 구조 보존율 |
| 스크린샷 QA (UI / 코드 캡쳐) | 정답률 |
| 복합 (이미지 + 텍스트 혼재 추론) | 정답률 |
| 환각 검증 (이미지에 없는 내용 질의) | 거절률 / 환각률 |

> **사용자 작성 비전 평가셋 업로드 후 위 9개에 매핑하고 빈 카테고리 보강안 추가 정리**.

### Gemma 4 visual token budget 비교 (필수)

Gemma 4는 이미지당 토큰을 70/140/280/560/1120 중 선택 가능. 같은 이미지에서 budget이 정확도/속도에 미치는 영향이 운영 비용 의사결정의 핵심.

- **Gemma 두 모델 한정**: 9 카테고리 × budget 3지점(70/280/1120) = 27셀
- Qwen 4종은 native 정책으로 1회 측정
- **파레토 프론트 작성**: x축 이미지당 토큰 비용, y축 정확도
  - Qwen 4종은 점, Gemma 2종은 곡선
  - "Qwen이 Gemma의 어느 budget 지점과 등가인지" 결정 가능

### 입력 표준화 (변수 통제)

- 모든 이미지를 **원본 + 1024px 긴 변** 두 가지로 준비
- 모델별 자동 리사이즈 정책이 다르므로 입력 해상도 고정
- 같은 이미지 + 같은 prompt를 6개 모델에 일괄 투입

### 비전 보조 지표

- **이미지당 토큰 비용**: 모델별 토크나이저 정책 차이 → 운영 비용 직결
- **해상도 robustness 곡선**: 224 / 512 / 1024 / 원본 → 저해상도에서 누가 덜 깨지는지
- **다중 이미지 입력**: 2~5장 동시 처리 가능 여부 + 성능 저하

## 7. 4단계: 에이전트 / 툴

> **원안 유지** — Ko-AgentBench로 사내 MCP 평가 대체 + 사내 회귀셋 보강.

### 평가 구성

- **Ko-AgentBench** (huggingface-KREW): 1차 공개 벤치 비교 (재현성 확보)
- **사내 MCP 회귀셋 50~100개**: 실제 함수 스키마 / 실패 로그 기반 (Ko-AgentBench로 100% 대체 불가)

### 측정 항목

- 함수 선택 정확도
- JSON schema 준수율
- 잘못된 툴 호출률
- 툴 호출 후 최종 답변 완결성
- 다단계 작업 성공률

### 분산도 측정

- temperature 0 고정 + **동일 프롬프트 5회 반복**
- 소형 모델은 일관성이 약점이라 분산 측정 필수
- Qwen3.6 시리즈는 agentic coding 강조라 가중치 ↑

### (4) 용도별 추천

- **한국어 요약 중심 워크로드** → 추천 N개
- **OCR / 한국어 문서 처리** → 추천 N개
