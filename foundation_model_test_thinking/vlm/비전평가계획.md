# 빅 VLM 평가 계획 (Image-to-Text)

> **본 문서는 100B 이상급 대형 Vision-Language 모델의 image-to-text 평가 계획**이다.
> 소형 6종 평가는 `../vsm/비전평가계획.md` 참조.
> 두 평가는 **동일한 VLMEvalKit 프레임워크 + 한국어 벤치마크 6종 + 50/30/20 가중치**를 공유하므로,
> 본 문서는 빅모델 고유 항목(라인업·인프라·양자화·교차 비교)만 집중 기술한다.

---

## 1. 개요

### 1.1 목적

100B+ 급 대형 멀티모달 모델의 한국어 image-to-text 품질을 측정하고, **소형 6종(`vsm/`) 결과와 직접 비교**해 다음을 결정한다.

- 빅모델이 카테고리별로 얼마나 우월한지 (사이즈 ROI)
- 소형으로 충분한 워크로드 vs 빅모델이 필수인 워크로드 분리
- 운영 비용 (멀티 GPU 점유 시간 / 토큰당 비용) 대비 품질 이득

### 1.2 적용 범위

- **포함**: 빅 VL 모델의 image-to-text (OCR · 문서 · 표/차트 · 실세계 장면 · 자유 서술형)
- **제외**: 영상 / 이미지 생성 / 음성 / 임베딩 (vsm과 동일)

### 1.3 평가 원칙

소형 평가와 동일 (재현 가능성·업무 정합성·자동화·다축 평가).
**추가 원칙**: 빅모델은 Qwen 공식 published 점수가 존재하므로, **재현 점수가 published와 ±5pt 이내**인지 환경 정상성 1차 검증한다.

## 3. 환경 (확정 / 결정 필요)

### 3.1 추론 환경

| 항목 | 값 |
|---|---|
| 추론 엔진 | gpustack 2.1.3 + vLLM 0.20.0 (vsm과 동일) |
| 컨텍스트 캡 | 200K |
| 추론 모드 | non-thinking 통일 |
| API | GPUStack OpenAI-compatible (`http://127.0.0.1:18090/`) |
| Expert Parallelism | `--enable-expert-parallel` 권장 (Qwen 모델 카드 가이드) |
| Tensor Parallelism | 8-GPU 단일 노드 (vLLM 공식 예시 기준) |

### 3.2 양자화 정책 — vsm과 다름 (결정 필요)

> **vsm은 비양자화(BF16) 통일이지만, 빅모델은 BF16이 8×80G H100에 안 들어감.**

| 모델 | BF16 | FP8 | GPTQ-Int4 |
|---|---|---|---|
| Qwen3.5-122B-A10B | ~244GB → 8×80G OK | ~122GB → 4×80G OK | ~61GB → 2×80G OK |
| Qwen3.5-397B-A17B | ~794GB → 8×80G **불가** | ~397GB → 8×80G **빠듯** (KV cache 고려 시 어려움) | ~199GB → 4×80G OK |

**제안**:
- **122B**: BF16 (비양자화)
- **397B**: FP8 (BF16 불가)
- 양자화 손실 분리 측정: 122B BF16 vs 122B FP8 미니 비교 (50~100문제) 1회 → "397B FP8 점수에서 양자화 손실 빼면 어디쯤인지" 추정
- 또는 두 모델 다 FP8로 통일해서 양자화 변수 제거 (대신 vsm BF16 비교 시 1단계 차이 인지)

이 결정에 따라 결과 해석이 달라지므로 **사용자 확정 필요**.

### 3.3 사전 호환성 검증 (Phase 1 진입 전)

- [ ] Qwen3.5-122B-A10B BF16 vLLM 0.20.0 로딩 (8×80G + EP 설정)
- [ ] Qwen3.5-397B-A17B FP8 vLLM 0.20.0 로딩 (8×80G + EP 설정)
- [ ] GPUStack에서 빅모델 등록·서빙 가능 여부 (단일 노드 점유 시간 운영 영향 확인)
- [ ] 200K 컨텍스트 vLLM 메모리 헤드룸 확인

## 4. 평가 체계 (vsm과 동일 — 요약)

> 자세한 정의는 `../vsm/비전평가계획.md` Section 3~5 참조.

### 4.1 카테고리 / 가중치

| 카테고리 | 가중치 |
|---|---|
| 문서 OCR·구조 이해 | 50% |
| 실세계 장면 텍스트 | 30% |
| 자유 서술형 종합 역량 | 20% |

### 4.2 트랙 A — 한국어 6 + 보조 영어 2

K-DTCBench / KO-VLM-Benchmark / KRETA / MTVQA(KR) / K-MMBench(선별) / KOFFVQA + (보조) OCRBench, POPE.

### 4.3 트랙 B — 커스텀 4

B-1 환각 / B-2 한국어 VL / B-3 포맷 준수 / B-4 지연시간.

> **빅모델용 데이터셋은 vsm과 동일 골든셋 사용** — 결과 직접 비교 가능.

## 5. 빅모델 고유 항목

### 5.1 Published 점수 재현 검증

Qwen3.5-122B-A10B / 397B-A17B는 Qwen 공식 카드에 VLMEvalKit 점수 공개되어 있음.

- 본 환경(GPUStack + vLLM 0.20.0 + FP8 또는 BF16) 결과가 published 대비 **±5pt 이내**인지 1차 검증
- 차이가 클 경우: 양자화 손실 / SPLIT_THINK 미적용 / vLLM 버전 / 입력 전처리 중 원인 진단
- **vsm 평가에서는 이 검증 불가** (소형 모델 대부분은 published VLMEvalKit 점수 부재)

### 5.2 운영 비용 측정 (vsm에 없는 항목)

- **단일 추론 호출당 GPU 점유 시간** (8×80G 기준)
- **토큰당 비용 추정** (전력·VRAM 임대 비용 환산)
- **최대 동시성** — 빅모델은 단일 노드 점유로 동시성이 1~4 수준에 묶임
- **콜드 스타트 시간** (모델 로딩 5~15분 가능, 점유 스케줄링 영향)

### 5.3 사이즈 ROI 곡선 (vsm 결과와 교차)

vsm/ 6모델과 본 평가 빅모델의 카테고리별 점수를 한 차트에 매핑:

```
x축: 활성 파라미터 (3B → 4B → 27B → 31B → 10B → 17B)
y축: 카테고리 점수
선: 카테고리별 (문서 OCR / 실세계 / 자유 서술형)
```

- "활성 파라미터 17B → 10B 떨어뜨려도 점수 손실 작은 카테고리" = 소형 충분
- "활성 27B Dense가 17B MoE보다 잘하는 카테고리" = Dense 강점
- "397B만 통과하는 카테고리" = 빅모델 필수 워크로드

## 7. 실행 순서

### 7.1 Phase 0 — 사용자 확정

1. Qwen3.6 빅 변종 출시 여부 / 평가 포함 여부
2. 양자화 정책 (122B BF16 + 397B FP8 / 둘 다 FP8 / 기타)
3. 운영 인프라 점유 일정 (8×80G 노드 점유 가능 시간대)

### 7.2 Phase 1 — 사전 검증 (3~5일)

- 빅모델 GPUStack 등록 + vLLM 0.20.0 + EP 설정 검증
- `verify_api.py` (vsm 동일) — 6 모델 → 빅모델 2~4개로 확장
- Qwen published 점수 재현 미니 테스트 (KOFFVQA 275 또는 K-DTCBench 240)

### 7.3 Phase 2~5 — vsm과 동일 순서 (단, 각 단계 시간 ↑)

```
Phase 2: 트랙 A 한국어 6개 (작은 것부터: KOFFVQA → K-DTCBench → ...)
Phase 3: 트랙 B 커스텀 4개
Phase 4: 빅모델 고유 — 양자화 손실 분리 측정 (122B BF16 vs FP8)
Phase 5: vsm 결과와 합쳐서 ROI 곡선 / 종합 리포트
```

### 7.4 비용 / 시간 추정

- 트랙 A 메인: 5,800 샘플 / 모델 × 2~4 모델 = **11,600~23,200 호출**
- 트랙 A 보조 (서브샘플): ~2,000 / 모델 × 2~4 = **4,000~8,000 호출**
- 트랙 B: ~600 / 모델 × 2~4 = **1,200~2,400 호출**
- **합계**: 약 17,000~34,000 호출
- 빅모델은 호출당 **3~6초** (vsm 2~3초 대비 2배), 동시성 1~4
- **모델당 12~20시간**, 4모델 순차 시 **48~80시간**
- 8×80G 노드 점유 일정 협의 필요
